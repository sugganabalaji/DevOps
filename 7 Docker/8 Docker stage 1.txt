The Docker Client is where users interact with Docker. The command does not create a container itself. Instead, It sends a request to the Docker Daemon.

The Docker Daemon (dockerd) is the main Docker service. It receives requests from the client. It is responsible for

Pulling Images
Building Images
Running Containers
Stopping Containers
Creating Networks
Creating Volumes

Linux Kernel
-------------
Docker uses Linux Kernel features like

Namespaces
Cgroups
OverlayFS

instead of virtualization.

This is why containers are lightweight.

Docker containers are not VMs — they use Linux kernel features:

Namespaces → provide isolation
 PID (process isolation)
 NET (network isolation)
 MNT (filesystem isolation)

cgroups (control groups) → manage resource limits
CPU
Memory
I/O

Namespaces provide isolation (PID, network, mount, etc.), ensuring containers don’t see each other’s resources.

cgroups control resource limits like CPU and memory, preventing one container from consuming all system resources.”

OCI (Open Container Initiative)
==============================
What is OCI?

The Open Container Initiative (OCI) is an open standard that defines how container images and runtimes should work so that containers are portable across different platforms.

It was launched in 2015 under the Linux Foundation with contributions from companies such as Docker, Red Hat, Google, and many others.

Why OCI Was Needed ?
-----------------
Before OCI:
-----------
Every vendor could have used its own image format.
Images built on one platform might not run on another.
There was no common specification.

OCI solved this by defining standard specifications.

OCI Specifications
---------------------
OCI mainly defines:

Image Specification
----------------
Standard image format
Image layers
Image manifest

Runtime Specification
-----------------------
How containers are created and run
Process execution
Filesystem layout
Namespaces and cgroups usage


Because Docker images follow the OCI Image Specification, the same image can also run on OCI-compliant runtimes such as:

containerd
CRI-O
Podman

This interoperability is one of the biggest advantages of OCI.

docker attach
-------------
is used to attach your terminal to the standard input, output, and error streams of the main process running inside a container.
It allows you to interact with the container's main process as if you were running it directly in your terminal.

Example: attaching/connecting to main wire
if you use exit command, container is stopped

# docker attach testcontainer
# exit ===> not recommended ===> use #ctrl+pq
# docker ps -a
# docker start testcontainer

docker exec
-----------
is used to run a new command in an already running container.
This command allows you to start additional processes inside the container independently of the main process.

Example: connecting to additional process
if you use exit command, container will not stop

docker attach interacts with the container's main process (PID 1).
docker exec starts a new, separate process inside the container.

EXEC is preferred

# docker exec -it testcontainer /bin/bash
# exit : not recommended ---> use #ctrl+pq
# docker ps -a
Safe
