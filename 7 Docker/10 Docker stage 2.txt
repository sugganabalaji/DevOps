What is a Docker Image?
-------------------------
A Docker Image is one of the most fundamental concepts in Docker. Before you can run a container, you must have an image.

Think of an image as a blueprint or template from which containers are created.

A Docker Image is a read-only template that contains everything needed to run an application:

Application code
Runtime (Java, Python, Node.js, etc.)
Libraries
Dependencies
Configuration files
Operating system components

Once an image is created, it cannot be modified directly. When you run it, Docker creates a writable container layer on top.

==============================================================================================================================
If you want to automate all these use Dockerfile

DOCKERFILE
----------

It is used to automate image creation.
Inside Dockerfile we use components to do our works.
Components will be on Capital Letter.
In Dockerfile D will be capital.
We can create image directly without container help
To create image from file we need to build it.

A Dockerfile is a text file containing a set of instructions used to build a Docker image automatically.

Instead of manually creating a container and installing software every time, we write a Dockerfile once and Docker builds the image consistently.

Docker Build is the process of converting a Dockerfile into a Docker Image.

COMPONENTS:
----------

FROM       : used to get base image
RUN        : used to run linux commands during (image creation) build time
CMD        : used to run linux commands (After container creation) run time
ENTRYPOINT : high priority than cmd. Defines the main executable of the container.
COPY       : to copy local files to container
ADD        : to copy internet files to container
WORKDIR    : to open req directory
LABEL      : to add labels for docker images
ENV        : to set env variables (inside container)
ARGS       : to pass env variables (outside containers)
EXPOSE     : Documents the port the application listens on. It does not publish the port to the host.

Dockerfile --> Docker Build -->  Image --> Container

.dockerignore : Docker ignores them. Files which are unnecessarily increase build time. [logs, .git, node modules etc]

Example 2
===========
RUN will execute while image creation
CMD will execute after container creation

Only one CMD should exist.

If multiple CMD instructions are present, only the last one is used.

ls
mv Dockerfile Dockerfile1
ls

vi Dockerfile

FROM ubuntu
RUN apt update -y
RUN apt install git maven tree apache2 -y
RUN touch file1
RUN apt install python3 -y
CMD apt install mysql-server -y

Note already first few lines are execute, it will not execute again, it will run last lines

CMD will not execute, because it will execute after container creation.

-- docker build -t balaji:v2 .
-- docker images

-- docker run -it --name cont2 balaji:v2   [don't use -d here for now to see the installation]
