Docker VOLUMES:
---------------
Docker volumes are a way to persist data generated by and used by Docker containers.
Volumes are stored on the host filesystem outside the container's filesystem, which means they  are not deleted when the container stops or deleted.
This makes them ideal for managing persistent data.

In Short
-------

If you want to store the data in container use volumes.
Volume is just a folder/directory in the container.
containers use host resources (cpu, ram, )
We will create a Directory(volume) in a host machine.
This Directory we attach to the containers.
volume can be shared to multiple containers at the same time.
At a time we can share single volume to multiple Containers.
Data inside volume will store on local/host machine file system.
If any data put in Directory available in Container.
If any data put in Container available in Directory.
If any data delete in Directory removed in Container.
If any data delete in Container removed in Directory.
It is Bidirectional.
Directory is physically exists in host machine, and virtually attached in containers.
If delete entair container Data still available in Directory.
EBS volumes also can be monted to containers.


Four Storage Options
    ├── Named Volume  [We can give the name of the volume]
    ├── Anonymous Volume [No name(nasty name) is given]
    ├── Bind Mount [A Bind Mount maps a host directory to a container directory.]
    └── tmpfs Mount [Temparory purpose]

1. What is a Docker Volume?
---------------------------
A Docker Volume is Docker-managed persistent storage that allows data to survive container deletion and recreation. It is the preferred way to store application data such as databases and Jenkins home directories.

2. What is the difference between a Named Volume and a Bind Mount?
----------------------------------------------------------------
Named Volume: Managed by Docker and stored in Docker's internal volume directory. Best for persistent application data.
Bind Mount: Maps a specific host directory into the container. Best for development, configuration files, and sharing source code.

3. What is an Anonymous Volume?
-----------------------------
An Anonymous Volume is a Docker-managed volume created automatically without a user-defined name. It receives a random ID, making it difficult to identify and reuse.

4. What is tmpfs?
----------------
A tmpfs mount stores data in the host's memory (RAM) instead of on disk. The data is lost when the container stops or is removed, making it ideal for temporary caches, session data, and sensitive information that should not be written to disk.

Docker Compose
-------------

Docker Compose is a tool that allows you to define and run multi-container Docker applications using a YAML file (docker-compose.yml). Instead of running multiple docker run commands manually, you can define everything in one file and start your services with a single command.

Docker Compose is a tool for defining and running multi-container Docker applications.

With Docker Compose, you can use a YAML file to define the services, networks, and volumes required for your application, and then bring up the entire stack with a single command.

It is a tool used to create multiple containers.

  It will work on single host.

we can create, stop, start and delete all containers together

we can write a file called docker-compose which will be on yaml format.
