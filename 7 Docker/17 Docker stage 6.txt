Docker Networking
===================

Docker networking are used to make communication between the multiple containers that are running on same or different docker hosts.

Different Docker Networks
-------------------------
 --> Bridge Network = Same hosts (if 2 containers wants to communicate with each other in same docker host machine.)
                      container gets its own IP.
                      The Bridge network is the 'default network' for containers on a 'Single Docker host'.
                      When you install Docker, it automatically creates a bridge network called 'bridge'.

                    Host Machine

             +----------------------+
             |     docker0 Bridge   |
             +----------+-----------+
                        |
        -------------------------------
        |             |              |
        ▼             ▼              ▼
   Container1    Container2    Container3
   172.17.0.2    172.17.0.3    172.17.0.4  --> these are private IPs

Docker creates a virtual bridge (docker0) and assigns private IP addresses to containers.


 --> Overlay Network = Different hosts (2 containers want to communicate with each other in different docker hosts).
                       Overlay networks connect containers running on different Docker hosts.
                       Containers communicate as if they were on the same network.
                       Docker Swarm uses Overlay Network.

 --> Host Network = if you want to use HOST meaning EC2 networking. With the Host network, the container shares the host's network
                     stack. No container IP, No NAT, No port mapping. The application listens directly on the host network.
                    Highest network performance
                    No NAT
                    Low Latency
                    But, Port Conflicts and Less Isolation

 --> None Network = if you don't want to expose any application. No networking at all. Container has no internet, No external
                    communication , only localhost. use cases are Security testing, Offline processing, Sensitive workloads

 --> Macvlan = Macvlan gives each container its own MAC address and IP address on the physical network.
               The container appears as a separate device on the LAN. use cases: Legacy applications, DHCP based env, Network
               Appliances , Applications requiring direct LAN visibility

1. What is the default Docker network?
--------------------------------------
The default network is the bridge network, which allows containers on the same host to communicate using private IP addresses.

2. What is the difference between the default bridge and a user-defined bridge?
------------------------------------------------------------------------------
Default bridge: Containers communicate by IP address unless additional configuration is done.
User-defined bridge: Provides built-in DNS, allowing containers to communicate using container names (for example, web can reach db by name). This is the recommended approach.

3. When should you use Host networking?
------------------------------------------
Use the host network when you need maximum network performance and can tolerate reduced isolation, such as for monitoring agents or high-performance network applications.

4. What is an Overlay network?
-------------------------------
An Overlay network connects containers across multiple Docker hosts. It is primarily used with Docker Swarm to enable secure, multi-host container communication.

5. What is a Macvlan network?
------------------------------
A Macvlan network assigns each container its own MAC address and IP address on the physical network, making the container appear as a separate machine on the LAN. This is useful for legacy applications and environments where containers must be directly reachable by other devices.

1. What is Docker Swarm?
-------------------------
Docker Swarm is Docker's native orchestration platform that manages multiple Docker hosts as a single cluster.

2. What is the difference between a Manager and a Worker?
-------------------------------------------------------
| Manager                 | Worker                    |
| ----------------------- | ------------------------- |
| Controls the cluster    | Runs tasks/containers     |
| Schedules services      | Executes assigned work    |
| Maintains cluster state | Cannot manage the cluster |


3. What is a Service?
----------------------
A Service defines the desired state of an application in Swarm, including the image, number of replicas, networking, and update behavior.

4. What is a Replica?
-----------------------
A replica is one running instance (task/container) of a service. Multiple replicas provide scalability and high availability.

5. What is a Stack?
------------------------
A Stack is a collection of related services deployed together from a Compose file using docker stack deploy.

6. What is an Overlay Network?
-------------------------------
An overlay network is a virtual network that enables containers running on different Swarm nodes to communicate securely.

7. What are Docker Secrets?
-----------------------------
Docker Secrets securely store sensitive information (such as passwords and certificates) and make it available only to authorized services at runtime.

8. What is a Rolling Update?
-----------------------------
A rolling update replaces service replicas gradually with a new version, reducing or eliminating application downtime.

9. How do you scale a service?
-----------------------------
docker service scale internetbanking=5

10. How do you roll back a failed update?
--------------------------------------
docker service rollback internetbanking

This restores the service to its previous working version.



Replicated Service vs Global Service
=====================================

Replicated Service
------------------
Scaling up or down by giving a desired number of replicas

It does not guarantee to run one replica on each node.

After deleting a worker node, it will still distribute the same number of replicas mentioned while running to the available nodes.

Applications are horizontally scaled up or down.

Example: A web server has 5 replicas.

Global Service : If we want every node to have a container which has a some service to run.
--------------
A global service in Docker Swarm is a service that runs a single task/container on each node in a swarm. Global services are used to monitor containers that want to run on a Swarm node.

Can not scale up or down by giving a desired number.

It guarantees to run one replica on each node.

After deleting a node, the total replica number will decrease by one.

Ideal for those that need one instance per node, like a monitoring agent.

Example: A log collector is running on each node to collect logs.
-------------------------------------------------------------------
In the below example, we are not mentioning any replicas, but as it is global service, it will create a replica in all nodes

vi docker-compose.yml

version: "3.8"
services:
  global-nginx:
    image: nginx
    deploy:
      mode: global
    ports:
      - "80:80"

docker stack deploy -c docker-compose.yml global-stack

docker service ls

Command
---------

docker service create --name nginx-global --mode global --publish 80:80 nginx


docker service ps nginx-global
