PLAY with Branches in github

Branch Protection Rules are repository settings in Git platforms like GitHub, Bitbucket that prevent risky or unauthorized changes to important branches (such as main, master, or release). They help ensure that code reaches protected branches only after meeting your team's quality and review requirements.

Why use Branch Protection Rules?

Without protection, anyone with write access could:

Push code directly to main
Merge code that hasn't been reviewed
Merge code with failing tests
Force-push and rewrite commit history
Accidentally delete the branch

Branch protection helps avoid these situations.


| Rule                                   | Recommendation   |
| -------------------------------------- | ---------------- |
| Require Pull Request                   | ✅ Yes            |
| Require approvals                      | 2 reviewers      |
| Dismiss stale approvals                | ✅ Yes            |
| Require conversation resolution        | ✅ Yes            |
| Require status checks                  | ✅ Yes            |
| Require successful build               | ✅ Yes            |
| Require unit tests                     | ✅ Yes            |
| Require code coverage threshold        | Optional         |
| Require branch up to date before merge | ✅ Yes            |
| Prevent force push                     | ✅ Yes            |
| Prevent branch deletion                | ✅ Yes            |
| Restrict direct push                   | ✅ Yes            |
| Require signed commits                 | Optional         |
| Linear history                         | Recommended      |
| Require merge queue                    | For larger teams |
